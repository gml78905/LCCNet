# log.md

> 이 파일은 실험 종료 후 결과를 어떻게 정리하고 저장할지에 대한 규칙을 정의한다.  
> 모든 실험은 실행만으로 끝나지 않으며, 반드시 정리까지 완료되어야 한다.  
> 본 프로젝트에서는 실험 종료 후 `/save <name>` 스킬을 통해 실험 결과를 정리한다.  
> 각 실험의 **자세한 분석은 실험 결과 폴더에 저장**하고, **핵심 수치와 속도 요약만 `workflow/experiments.md`에 기록**한다.

---

## 1. 목적

이 파일의 목적은 다음과 같다.

- 실험이 끝난 뒤 결과 정리 과정을 표준화한다
- 상세 기록과 요약 기록의 역할을 분리한다
- 실험 결과가 흩어지지 않도록 한다
- 이후 다시 결과를 찾아보거나 비교할 수 있도록 한다
- `experiments.md`가 너무 길어지지 않도록 한다

즉 이 파일은 **실험 종료 후 기록 workflow**를 정의한다.

---

## 2. 기본 원칙

### 2.1 실험은 실행이 아니라 정리까지 끝나야 완료다
실험이 성공적으로 실행되었더라도, 결과 정리가 없으면 완료된 실험으로 간주하지 않는다.

실험 완료의 최소 조건은 다음과 같다.

1. 실행이 끝남
2. 주요 결과를 확인함
3. `/save <name>`으로 정리함
4. 상세 기록이 실험 결과 폴더에 저장됨
5. 요약이 `workflow/experiments.md`에 반영됨

---

### 2.2 상세와 요약은 분리한다
본 프로젝트에서는 실험 기록을 두 층으로 나눈다.

#### 상세 기록
각 실험의 자세한 결과와 분석은 **실험 결과 폴더**에 저장한다.

포함할 수 있는 내용:
- 실험 설정
- train / val curve
- metric 전체
- pairwise 결과
- 속도 측정 상세
- GPU 사용량
- 정성 시각화
- 실패 원인 분석
- 해석
- 다음 실험 아이디어

#### 요약 기록
핵심 수치와 속도, 짧은 분석 요약만  
`workflow/experiments.md`에 저장한다.

포함할 내용:
- 실험 이름
- 상태 태그
- 핵심 성능
- 속도 / 자원 요약
- 짧은 해석
- 상세 기록 위치
- 다음 액션

---

### 2.3 실험 이름은 반드시 명확해야 한다
`/save <name>`에 들어가는 `<name>`은 나중에 바로 이해할 수 있어야 한다.

좋은 예:
- `tribaseline_onebatch`
- `tribaseline_training`
- `loop_consistency_v1`
- `recurrent_context_v0`

좋지 않은 예:
- `test`
- `final`
- `new`
- `real_final_2`

실험 이름은 가능한 한
- 무엇을 했는지
- baseline 대비 무엇이 달라졌는지
를 알 수 있게 짓는다.

---

## 3. `/save <name>` 사용 규칙

### 3.1 언제 사용하는가
`/save <name>`은 다음 경우에 사용한다.

- one-batch debug가 끝났을 때
- 짧은 학습 실험이 끝났을 때
- 주요 ablation이 끝났을 때
- 실패 실험이더라도 기록할 가치가 있을 때
- 중간 checkpoint 기준으로 결과를 남기고 싶을 때

즉 성공 실험만 저장하는 것이 아니라,  
**나중에 다시 볼 가치가 있는 실험은 모두 저장**한다.

---

### 3.2 `/save <name>`이 하는 일
`/save <name>`은 실험 종료 후 아래를 수행하는 용도로 사용한다.

1. 해당 실험의 상세 기록을 정리한다
2. 상세 기록을 실험 결과 폴더에 저장한다
3. `workflow/experiments.md`에는 요약만 남긴다

즉 `/save`는 단순 메모가 아니라,  
**실험 종료 후 공식 기록 절차**이다.

---

### 3.3 `/save <name>`에 포함되어야 하는 정보
저장할 때 최소한 아래 정보가 있어야 한다.

- 실험 이름
- 날짜
- 목적
- 핵심 변경점
- baseline 정보
- 핵심 성능
- 속도 / 자원 사용량
- pairwise 결과 요약
- 짧은 해석
- 다음 액션
- 상태 태그

---

## 4. 상세 기록 저장 위치

각 실험의 자세한 기록은 **실험 결과 폴더**에 저장한다.

예시 구조:

- `results/tribaseline_onebatch/`
- `results/tribaseline_training/`
- `results/loop_consistency_v1/`

각 폴더 안에는 다음과 같은 파일이 있을 수 있다.

- `summary.md`
- `metrics.json`
- `train.log`
- `val.log`
- `plots/`
- `visualizations/`
- `notes.md`

구체적 구조는 바뀔 수 있지만,  
핵심은 **각 실험의 자세한 결과가 하나의 폴더 단위로 묶여 있어야 한다**는 점이다.

---

## 5. `workflow/experiments.md`에 남기는 것

`workflow/experiments.md`에는 아래만 남긴다.

- 실험 이름
- 상태 태그
- 목적
- 핵심 변경점
- 핵심 성능
- 속도 / 자원 요약
- 짧은 분석 요약
- 상세 기록 경로
- 다음 액션

즉 `experiments.md`는  
**workflow 인덱스 + 실험 요약 파일**이지,  
상세 보고서가 아니다.

---

## 6. 상태 태그 규칙

실험 요약에는 반드시 아래 태그 중 하나를 붙인다.

- `planned`: 아직 실행 전
- `running`: 현재 실행 중이거나 결과를 정리 중인 상태
- `keep`: 의미 있는 결과가 있었고 이후 방향에 반영할 가치가 있음
- `discard`: 현재 방향에서는 다시 수행할 필요가 낮음
- `revisit_later`: 지금은 우선순위가 낮지만, 나중에 다시 검토할 가치가 있음
- `inconclusive`: 결과가 애매해서 명확한 결론을 내리기 어려움

실험이 끝난 뒤 `/save <name>`을 수행할 때는  
반드시 이 중 하나로 상태를 정리한다.

---

## 7. 기록 흐름

실험이 끝난 뒤의 기본 흐름은 아래와 같다.

1. 실행 결과 확인
2. 핵심 metric / 속도 / pairwise 결과 정리
3. `/save <name>` 실행
4. 상세 기록을 실험 결과 폴더에 저장
5. `workflow/experiments.md`에 요약 반영
6. 다음 액션 기록

즉:
- 상세는 결과 폴더
- 요약은 workflow

로 분리한다.

---

## 8. 꼭 기록해야 하는 요약 항목

`workflow/experiments.md`에는 최소한 아래를 남긴다.

### 8.1 성능
- total metric 또는 핵심 loss
- CL / CR / LR 성능 요약
- baseline 대비 개선 여부

### 8.2 속도
- epoch 시간
- batch time
- GPU 메모리
- input resolution
- batch size

### 8.3 짧은 분석
예:
- train/val 모두 안정적으로 감소함
- CR pair만 여전히 어려움
- 속도는 baseline 대비 증가했지만 감당 가능
- loop consistency 추가 효과가 작음
- recurrent context가 초기 수렴을 안정화함

즉 상세 분석은 결과 폴더에 남기고,  
여기에는 **짧고 핵심적인 해석만** 남긴다.

---

## 9. 실패 실험도 저장한다

실험이 실패했더라도 아래 조건이면 저장한다.

- 다시 반복하지 말아야 할 이유가 분명함
- 실패 원인이 의미 있음
- 이후 방향 결정에 참고할 가치가 있음

즉 실패했다고 `/save`를 생략하지 않는다.  
오히려 `discard` 또는 `inconclusive`로 정리하는 것이 중요하다.

---

## 10. 중간 저장 규칙

긴 학습이나 여러 단계 실험에서는 중간 결과도 저장할 수 있다.

예:
- `recurrent_context_v0_epoch5`
- `loop_consistency_v1_shortrun`

단, 중간 저장도 이름이 명확해야 하며,  
최종 실험과 혼동되지 않도록 한다.

---

## 11. 세션 종료 전 체크리스트

실험이 끝난 날에는 세션 종료 전에 반드시 아래를 확인한다.

- `/save <name>`을 수행했는가
- 상세 결과가 실험 결과 폴더에 저장되었는가
- `workflow/experiments.md`에 요약이 반영되었는가
- 상태 태그가 붙었는가
- 다음 액션이 남았는가

이 중 하나라도 빠졌으면 실험 정리가 완료된 것이 아니다.

---

## 12. 권장 저장 형식

실험 결과 폴더의 상세 기록은 가능하면 아래 형식을 권장한다.

### `summary.md`
- 실험 목적
- 설정
- 결과
- 해석
- 결론

### `metrics.json`
- 핵심 metric
- pairwise metric
- 속도 / 자원 사용량

### `notes.md`
- 추가 메모
- 실패 원인
- 다음 아이디어

즉 사람이 읽기 쉬운 형식과,  
나중에 자동으로 파싱하기 쉬운 형식을 함께 남기는 것이 좋다.

---

## 13. 한 줄 요약

본 프로젝트에서 실험이 끝나면 `/save <name>`을 통해 **상세 분석은 실험 결과 폴더에 저장하고, 핵심 수치와 속도 및 짧은 분석 요약만 `workflow/experiments.md`에 반영**한다.
